## Draft takeover, waiting and Stop

A human program edit takes over the shared draft. Automatic replacement and
submission remain paused until the next explicit Sidekick instruction. Root
revision/liveness checks happen at actual admission, including after suspended
preflight. Late acknowledgements clear only their own draft revision. Chat and

## Output-read contract

Submit returns status, the exact entry ID and a ready-to-use EntryOutput read,
without an output body, preview or summary. Completion is after teardown, not
merely a root Close. A failed entry includes its actual reason and read
instruction; a refusal invents no entry.

EntryOutput defaults to the latest entry. entry accepts an exact entry ID or
negative index (-1 latest, -2 previous); zero/positive indexes are unavailable.
offset is signed Unicode code points; negative offsets count from snapshot end,
before-start clamps to zero and explicit zero reads from the beginning.
limit is a positive integer, default 4096. Omitted offset means -limit: the
requested tail. There is no additional feature-specific hard maximum or
unbounded spelling. This supersedes the initial fixed-4096 proposal.

Resolve relative target and offset once. Return the exact chunk with actual
entry, observed range/status and adjacent read invocations pinned to that entry,
absolute offsets and selected limit. A running read is an immediate unfinished
snapshot of already emitted output; it executes/resumes/waits for nothing.
Respect ordinary Output buffering. Empty/beyond-end ranges are truthful;
unknown/out-of-range entries refuse without substitution. No summary is added.
